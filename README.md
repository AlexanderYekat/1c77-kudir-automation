## Установка на новый компьютер

Обработка `kudir_export` пишет каждый запуск в новую папку `%KUDIR_PROTO_ROOT%\exchange\KUDIR4_<дата>_<NNN>`. Папки `exchange` и запуска создаёт сама.

1. **Переменная окружения `KUDIR_PROTO_ROOT`** — путь к папке проекта, где лежат `reports` и `1cv77`. Например, `setx KUDIR_PROTO_ROOT "D:\kudir\proga"`; затем перезапустить 1С: переменная читается при старте. Без неё обработка останавливается с сообщением «не задана переменная окружения KUDIR_PROTO_ROOT» и ничего не пишет. Проверки `reports/check_e0*.py` ищут запуски в `exchange` той же папки проекта.
2. **Обработки и прежние запуски копируются вручную.** Папки `1cv77-extforms` (файлы `.ert`, которые открываются в 1С) и `exchange` исключены из Git, клон их не содержит. В `exchange` — персональные данные покупателей; переносить её, только если прежние запуски нужны.
3. **Файл `kudir_source_id.txt` в каталоге информационной базы 1С** — одна строка `ctoksm-buh`. При переносе базы папкой файл переезжает вместе с ней. Если создавать его заново, значение должно быть тем же: к нему привязаны решения и постоянные ID в Python. Без файла выгрузка не запускается.

## Приоритет и начало работы

Последующие явные решения владельца имеют приоритет. Методический смысл задают №10/№11, технические детали — профильные №1/№2/№4. №00 даёт обзор, №12 определяет порядок выполнения. Сценарии не утверждают оставшиеся предложения №11 §14.2.

Перед реализацией проверить фактические файлы, ветку и незавершённые изменения. Следующий отдельный этап — Э0 плана №12: доработка и проверка полной выгрузки 1С по ТЗ №1 и №4. Затем — приём пакета в Python по №1/№2 на Э1. При начале работы явно прочитать перечисленные документы, относящиеся к этапу; одного плана недостаточно.

Все подробные планы Э0–Э13 собраны в [каталоге plans с оглавлением](plans/README.md). Каждый содержит подзадачи, чекпоинты и готовое поручение Cursor. Реализация идёт по [плану выгрузки 1С №13](plans/13-ПЛАН-ВЫГРУЗКИ-1С.md): Э0.1–Э0.3 приняты, текущий шаг и его статус — в [журнале](DOCS-EXPORT-PROGRESS.md); наличие планов следующих этапов не означает их реализации.

Устаревшие планы, аудиты, промпты и промежуточные замечания удалены из рабочей папки по поручению владельца. Принятые решения и актуальные замечания отражены в документах выше; прежние редакции доступны в истории Git. Старые материалы не следует повторно применять как действующие инструкции.
