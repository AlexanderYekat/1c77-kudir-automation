## Приоритет и начало работы

Последующие явные решения владельца имеют приоритет. Методический смысл задают №10/№11, технические детали — профильные №1/№2/№4. №00 даёт обзор, №12 определяет порядок выполнения. Сценарии не утверждают оставшиеся предложения №11 §14.2.

Перед реализацией проверить фактические файлы, ветку и незавершённые изменения. Следующий отдельный этап — Э0 плана №12: доработка и проверка полной выгрузки 1С по ТЗ №1 и №4. Затем — приём пакета в Python по №1/№2 на Э1. При начале работы явно прочитать перечисленные документы, относящиеся к этапу; одного плана недостаточно.

Э0 разбит в отдельном [плане выгрузки 1С №13](13-ПЛАН-ВЫГРУЗКИ-1С.md) на подзадачи Э0.1–Э0.7 с ручными чекпоинтами. Начать с Э0.1 — проверки основы и вызовов 1С. Cursor готовит код и инструкции, владелец запускает и проверяет в 1С; результат каждого чекпоинта фиксируется в журнале до перехода к зависимой подзадаче. Готовое поручение для начала приведено после Э0.7.

Следующий после выгрузки этап Э1 детализирован в [плане приёма пакета Python №14](14-ПЛАН-ПРИЁМА-ПАКЕТА-PYTHON.md): подзадачи Э1.1–Э1.6, автоматические проверки и итоговый запуск на пакете Э0. Наличие этого плана не меняет текущий шаг: сначала Э0.1.

Устаревшие планы, аудиты, промпты и промежуточные замечания удалены из рабочей папки по поручению владельца. Принятые решения и актуальные замечания отражены в документах выше; прежние редакции доступны в истории Git. Старые материалы не следует повторно применять как действующие инструкции.
