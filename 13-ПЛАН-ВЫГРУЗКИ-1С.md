# План выгрузки данных из 1С: этап Э0

Дата: 14.09.2026. Подробный рабочий план этапа Э0 из [общего плана №12](12-ПЛАН-РЕАЛИЗАЦИИ-И-ПРИЁМКИ.md). Номер этого документа — 13; это не этап Э13 общей приёмки программы.

Цель — до разработки Python получить и вручную проверить полный пакет v4/STABLE_DOCUMENT_V1 из 1С 7.7 в режиме FULL, со всеми кварталами охвата REFRESHED. Основные требования задают [ТЗ №1](01-ТЗ-1С-выгрузка-данных.md) и [ТЗ №4](04-ТЗ-1С-память-выгрузки.md); этот документ задаёт порядок работ и чекпоинты, не заменяет ТЗ. INCREMENTAL/REUSED остаётся на Э9 общего плана, приём пакета в Python — на Э1, сквозная проверка — на Э5.

Текущее состояние и результаты ручных проверок ведутся в [журнале](DOCS-EXPORT-PROGRESS.md). Перенос плана в отдельный файл не означает начала реализации.

## Порядок подзадач Э0 и ручные чекпоинты

Владелец запускает обработку и проверяет результаты в 1С вручную. Cursor готовит код, доступные проверки файлов и точную инструкцию для каждого запуска, затем разбирает переданные результаты. Порядок: Э0.1 → Э0.2 → Э0.3 → Э0.4 → Э0.5 → Э0.6 → Э0.7 → Э1. Это детализация Э0, не новый контракт обмена. Все подзадачи пока **не начаты**.

Работа выполняется по одной подзадаче до её чекпоинта. Перед передачей владельцу Cursor завершает доступную подготовку и собственные проверки. Успех чтения исходника или проверки текста не заменяет запуск 1С. До получения результата ручной проверки статус — «ожидает проверки в 1С»; зависимая подзадача не начинается. При ошибке Cursor исправляет текущую подзадачу и выдаёт обновлённую инструкцию, а не переносит ошибку дальше. Отсутствие ответа не означает успешной проверки.

Для каждого чекпоинта Cursor передаёт: изменённые файлы и способ установки в обработку; точные действия запуска с параметрами; что должно появиться в журнале/файлах; какие исходные значения 1С и строки CSV сверить; что вернуть для разбора. Инструкция должна использовать фактические имена процедур и элементов подготовленной обработки. После ответа владельца результат фиксируется в DOCS-EXPORT-PROGRESS.md: номер подзадачи, версия проверенного кода, параметры/дата запуска, выполненные проверки, ожидаемые и фактические значения, ошибки и следующий шаг. Версия — существующий commit либо контрольная сумма файла; новый commit для чекпоинта не обязателен.

Форматы, перечисления, состав файлов и обязательность полей берутся из ТЗ №1. Промежуточные выгрузки Э0.1–Э0.5 — диагностические, в отдельном незавершённом каталоге, без COMPLETE. Ограниченный пример допустим для проверки отдельной процедуры, но не выдаётся за полный охват. Приёмка Э0.7 выполняется на всей объявленной области. Проверочные запуски не создают и не меняют учётные документы ради примеров. Отсутствующий в базе случай отмечается как непроверенный; если он нужен для приёмки, фиксируется способ дальнейшей проверки, а не выдуманный успех.

## Э0.1. Проверить основу и вызовы 1С

- **Читать:** №1 §§2–7, 19–22, 26, 29; №4 §§3–4; фактические 1cv77/kudir_export.txt и 1cv77/Анализ-взаирасчетов.txt. При первом запуске прочитать README, №00 и границы потребителя в №2; методический смысл снимков уточнять по №10/№11.
- **Cursor делает:** проверяет рабочие изменения и существующий модуль; определяет точку запуска FULL и способ задания source_id/конца истории; готовит минимальную диагностическую проверку доступных реквизитов и API. Проверяет получение точного K от документа и Опер.Документ, позиции, номера проводки, аналитики и вызовов остатков. Подтверждённый выбор API повторно не выносится на согласование.
- **Владелец проверяет в 1С:** устанавливает подготовленный код, проверяет синтаксис и запускает диагностику на существующих документах. Сверяет документ из прямого обхода с тем же документом через операцию и доступность необходимых аналитик/границ. Возвращает журнал и ошибки с местом возникновения.
- **Чекпоинт КП0.1:** код запускается; для проверенных вызовов сохранены фактические результаты, одинаковый документ даёт одинаковый K, неопределённые возможности явно перечислены. Ошибки API, от которых зависят следующие подзадачи, устранены. Результат — проверенная техническая основа, ещё не выгрузка v4.

## Э0.2. Идентификаторы, CSV и незавершённый пакет

- **Читать:** №1 §§5–7, 21–22, 23.2–23.3, 27–30; №4 §§5, 8, 10, 13.
- **Cursor делает:** реализует устойчивые ID по STABLE_DOCUMENT_V1, сохранение точных позиций/системных строк, id_map и контроль коллизий. Готовит потоковую запись CSV, отдельный каталог запуска, WRITING и диагностику. Закрытие потоков и обработка ошибок действуют уже здесь; публикация COMPLETE ещё отключена.
- **Владелец проверяет в 1С:** запускает запись диагностического набора, повторяет чтение тех же объектов, проверяет восстановление системной ссылки в объект. Передаёт файлы и журнал; Cursor проверяет windows-1251, разделители, кавычки, многострочный текст, завершающие пробелы, уникальность ключей и совпадение ссылок. Недостающие текстовые крайние случаи можно проверить искусственными строками без изменения учётных документов.
- **Чекпоинт КП0.2:** повторное чтение сохраняет документные ID; позиции и ссылки не обрезаны, CSV читается без потери значений, ошибка не выдаёт успешный пакет и не затрагивает предыдущий. Изменение реквизитов/перенумерация проверяются по №1 §29 без редактирования рабочей базы ради теста; непроверенное отмечается явно. Постоянные ID Python здесь не реализуются.

## Э0.3. Движения 62.1/62.2 и факты оплат

- **Читать:** №1 §§4, 6–12.1, 18–22, 23.3, 25, 27–29; №4 §§4–5, 7–8.
- **Cursor делает:** заменяет старую выгрузку payments/is_target на ledger62 по текущему контракту, с нужными сторонами проводок, знаками, целыми копейками, ролями, аналитикой и исходными текстами. Обрабатывает CASH/BANK/MANUAL, возвраты, переносы и неизвестные группы без потери фактов. Функцию банковской первички оставляет владельцу по №1 §18; отсутствие реквизитов отражает явно.
- **Владелец проверяет в 1С:** сверяет выбранные кассовые, банковские и ручные события, имеющиеся возвраты/сторно/переносы с проводками и строками ledger. Для каждой выборки передаёт исходные суммы, счета/стороны и соответствующие строки CSV. Проверяет несколько строк одной выписки, если такой пример есть.
- **Чекпоинт КП0.3:** выбранные движения совпадают по сумме, знаку, стороне и аналитике; денежный вклад не удваивается переносом или двумя сторонами проводки. UNKNOWN не скрывает движение. Проверка не ограничивается общей итоговой суммой, способной скрыть взаимную компенсацию ошибок. Получение всего ledger потоковое; готовность пакета ещё не объявляется.

## Э0.4. Документы, основания и НДС

- **Читать:** №1 §§9–10, 13–19, 21, 23.3, 27–29; №4 §§6, 8.
- **Cursor делает:** выгружает обязательные документы всей области и доступные основания, исходные комментарии, суммы и агрегаты НДС с KNOWN/UNKNOWN. Обеспечивает согласованность document_id/source_document_id/id_map, чтение нужных данных без накопления всех документов и повторных обходов строк ради НДС. Не переносит в 1С сопоставление, которое относится к Python.
- **Владелец проверяет в 1С:** выбирает имеющиеся счёт, акт/реализацию, документы денежных событий и доступные корректировки; сверяет реквизиты, тексты, суммы и состав НДС с CSV. Для акта сверяет исходный комментарий со ссылкой на счёт. Возвращает примеры и выявленные расхождения.
- **Чекпоинт КП0.4:** обязательные документы и ссылки присутствуют, поля соответствуют источникам, недоступный НДС не записан как известный ноль, тексты сохранены. Ссылки не подменены произвольным первым документом. Отсутствие банковской первички отражено по ТЗ, реквизиты выписки не выданы за первичку.

## Э0.5. Прямые снимки, квартальные контроли и полнота охвата

- **Читать:** №1 §§4, 11, 19–23.4, 27–29; №4 §§7, 9, 12.
- **Cursor делает:** получает DAY_START на обязательных годовых/квартальных границах и BEFORE_DOCUMENT перед денежными документами в CUSTOMER и CUSTOMER_CONTRACT. Формирует полный набор аналитик по входящим остаткам, ledger и documents всей области. Отдельно получает четыре общих квартальных контроля и метаданные FULL/REFRESHED; они не заменяют аналитические снимки.
- **Владелец проверяет в 1С:** сверяет выбранные остатки на начало года/квартала и перед документом в обоих разрезах; проверяет, что сам документ не включён. Сверяет подписанное сальдо покупателя с суммой договорных сальдо и движение между границами. Отдельно проверяет общие квартальные Дт/Кт и текущий неполный квартал. Cursor готовит конкретную ведомость ожидаемых сверок по полученным данным.
- **Чекпоинт КП0.5:** обязательные ключи снимков представлены, совпавшая годовая/квартальная граница не задвоена; 62.1/62.2 объединены без повторного родительского итога. EMPTY/UNKNOWN различаются, неизвестные остатки не превращены в нули. Сверка известных значений выполняется с допуском 0 копеек. Расхождения классифицированы строго по №1 §27: допустимый WARNING остаётся видимым и не считается успешной сверкой; потеря обязательных фактов не маскируется предупреждением. Текущий квартал не объявлен полным, его недоступный календарный конец не заменён остатком на дату выгрузки.

## Э0.6. Сборка FULL, завершение и восстановление после сбоя

- **Читать:** №1 §§5, 20, 23.2–23.4, 27–30; №4 §§4–13.
- **Cursor делает:** объединяет подготовленные части в полный пакет из восьми файлов, добавляет проверки перед публикацией и разрешает COMPLETE только после их успеха и закрытия потоков. Проверяет run_id, схему, охват, происхождение кварталов, количества, ключи/ссылки и отсутствие ERROR. Обеспечивает освобождение структур и сохранность предыдущего успешного пакета. Готовит безопасный способ проверки прерываний записи и публикации в каталоге нового запуска.
- **Владелец проверяет в 1С:** выполняет успешный FULL, затем пользовательское прерывание и подготовленные контролируемые сбои при записи движений, документов, снимков и публикации; после сбоя повторяет FULL в том же сеансе. Возвращает журналы, состояния каталогов и замеры ресурсов по доступному способу, указанному Cursor. Не повреждает старый успешный пакет ради проверки.
- **Чекпоинт КП0.6:** успешный запуск публикует согласованный COMPLETE последним; прерванный запуск остаётся WRITING/FAILED и не заменяет прошлый успех. Повтор не дописывает новые строки к старым и не использует незавершённый результат. Потоки закрываются и рабочие структуры освобождаются. Измерения большого объёма и полная приёмка кеша остаются на Э9; обнаруженные сейчас ошибки памяти устраняются сейчас.

## Э0.7. Итоговая ручная приёмка выгрузки и передача в Python

- **Читать:** №1 §§24–30; №4 §15 в части FULL; критерии Э0 и Э1 общего плана №12.
- **Cursor делает:** готовит единый сценарий итогового FULL на всей объявленной области одной организации, перечень контрольных примеров и проверку файлов по №1 §28. Проверяет полученные файлы доступными средствами без разработки промышленного загрузчика Э1 и без запуска старого matcher. Сводит результаты КП0.1–КП0.6 в протокол, указывает оставшиеся UNKNOWN/WARNING и непроверенные случаи.
- **Владелец проверяет в 1С:** выполняет итоговый запуск и выборочную сверку исходных документов, движений, снимков и квартальных контролей по подготовленному списку; передаёт итоговый пакет и журнал. Простые примеры выбираются внутри полного пакета, остальные покупатели и движения не отфильтровываются.
- **Чекпоинт КП0.7:** сохранены пакет, версия кода, параметры охвата и протокол с фактическими результатами. Все обязательные проверки Э0 выполнены, ошибки реализации устранены, обязательные факты не потеряны; допустимые неизвестности обозначены по ТЗ. Невыполненная обязательная проверка оставляет Э0 непринятым. Отдельно перечислены испытания, отнесённые планом к Э9/Э13, без заявления об их успехе.
